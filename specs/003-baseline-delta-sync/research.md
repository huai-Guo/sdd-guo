Critical lifecycle correction: proposed baseline updates belong in the same feature branch/PR as implementation. Main/base baseline stays current until actual merge; the branch baseline describes the proposed branch tree. Keeping every baseline update out of a PR until after merge would require a second delivery and permit code/spec drift. Git supplies the proposed/current separation without an extra backend.
